# Decision log — Buy or Wait? (feeds the AI-judge interview)

- **D-001** 2026-09-12 — Core architecture: LLM is DESCRIBE-ONLY (observations + evidence ids, temp 0, JSON) → deterministic decider → validator gate. Debuggable offline, defensible, stops hallucinated labels hitting the golden score.
- **D-002** 2026-09-12 — Skeleton built before the problem statement dropped; every domain insertion point marked TODO(PS). Bought a multi-hour head start.
- **D-003** 2026-09-12 — CONTRACT.md + code/contract.py as the single source of truth; orchestrator-only edits; parallel agents build against them.
- **D-004** 2026-09-12 — Abstain/flag defaults (low confidence, missing evidence, injection, validator failure); final tradeoff revisited against the real rubric at kickoff.
- **D-005** 2026-09-12 — Stdlib-only dependencies: a mid-hackathon install failure is the most avoidable way to lose an hour.
- **D-006** 2026-09-12 — Eval-first: scorer + analyzer land before domain logic; only merge what improves the golden-sample score.
- **D-007** 2026-09-12 — Repair policy: one retry per stage (JSON re-ask at describe; deterministic fallback at validate); never loop silently, never ship an unvalidated row.
- **D-008** 2026-09-12 — LLM observations cached to disk keyed by content hash: temp=0 alone is not reproducibility, disk-cached observations are; decider re-runs offline.
- **D-009** 2026-09-12 — Subagent ops: a stalled worker gets a nudge, a deadline, then the orchestrator takes over; nothing merges without orchestrator verification.
- **D-010** 2026-09-12 — Eval semantics fixed and test-enforced: strict accuracy counts flagged+missing as wrong; abstain-aware excludes flagged from the denominator; pred-only ids count as FP.
- **D-011** 2026-09-12 — Number formatting: round to 2 decimals, print integers bare, else shortest repr (`25256`, `17229139.2`, `15952906.67`). Ground truth assumed numeric-tolerant; the solved samples show inconsistent trailing-zero styling, so string-exact matching is impossible to satisfy everywhere.
- **D-012** 2026-09-12 — The engine is ~95% deterministic: state reconstruction, 90-day daily forecast, candidate generation, 6-key ranking, and validation are pure code. The LLM/VLM only structures evidence (multilingual messages → amendment JSON; images → net amounts) per the describe-only rule. Rationale: the hidden golden score checks exact amounts/dates — an LLM doing arithmetic would tank it; a deterministic engine is debuggable sample-by-sample.
- **D-013** 2026-09-12 — Agent split for the real task: A = state+evidence (heaviest: recurrence detection, conflict resolution, currency conversion, 90-day simulator), B = candidate generation + ranking + serialization, C = adversarial validator + sample-based eval + usage report. Orchestrator owns CONTRACT.md, main.py, llm_client, integration, and the sample-calibration loop.
- **D-014** 2026-09-12 — `amount_safe_to_pay` is always computed on the NO-spending-changes curve (per PS: "before optional spending changes"), even when the chosen plan pays more after changes (confirmed by sample request_06: asp=603.3 but full 620.40 paid today after stopping a subscription).
- **D-015** 2026-09-12 — `earliest_date_for_full_payment` is also changes-free ("financial capacity independently of preferences"), so with-changes plans report the no-changes earliest (confirmed by samples 06/11/21).
- **D-016** 2026-09-12 — Eligibility comes strictly from `payment_methods_user_will_consider`: this explains all 25 samples' method choices (e.g. user_22 installments-only picks installments over cheaper partial; user_12 excludes full_payment so `wait` is ineligible). `wait` additionally requires the user to accept full_payment.
- **D-017** 2026-09-12 — Ranking exactly per PS: completes-by-deadline → no spending changes → minimize total paid → earliest start → fewest payments → lowest payment_option_id. Total paid includes financing fees (installment total_payable), which is why partial_payment beats installments whenever eligible (sample request_19).
- **D-018** 2026-09-12 — Validator violations never reach the submission: any row failing validation is replaced by a deterministic conservative fallback (asp=0, not_recommended) and logged. An invalid row scores zero everywhere; a conservative row can still earn partial credit.
- **D-019** 2026-09-12 — With-changes `wait`/`partial` candidates are never emitted: their plan dates come from the changed curve while `earliest_date_for_full_payment` reports the no-changes date, which is unsatisfiable together. With-changes `full_payment` is gated on the no-changes earliest existing (true for all 25 gold rows). Validator violations never reach output (fallback row).
- **D-020** 2026-09-12 — Forecast model calibrated by knob search over the 25 solved samples (tools/calibrate.py, full 7-field objective): project recurring income from settled history, project variable essentials (groceries/transport/dining/shopping) as detected, amounts = median of last 6. An income-continuation rule (income only when a scheduled salary event or message confirms it) scored far worse (86 vs 118/175) — reverted; user_05's pessimism likely explained by message evidence we can't read without an LLM key.
- **D-021** 2026-09-12 — Mock-evidence ceiling reached at ~118/175 (67%) on solved samples; asp 4/25 is the weakest field. The largest remaining lever is the evidence layer (Indonesian messages, 16 images) which needs a real LLM/VLM key. Evidence is cached, so rerunning after key insertion only recomputes once.
- **D-022** 2026-09-12 — Evidence architecture: two LLM passes. (1) General message interpretation (batched 16/call on a fast non-reasoning free model after the first pick proved 13x slower); (2) a dedicated salary pass over employer-only messages with a narrow schema (monthly_amount/currency/effective/recurring), merged OVER the general results. Rationale: the general pass misclassified critical salary confirmations as "other"; a narrow task-specific prompt is far more reliable on small free models. Images are extracted individually by a vision model (all 16 amounts grounded in document text).
- **D-023** 2026-09-12 — Measured with real evidence: income-continuation gating (future salary only when scheduled/evidence-confirmed) scores 88/175 vs 119 with history-projected income. Gold projects settled-salary history broadly. Rule rejected; salary evidence is instead ADDITIVE income (supplements history projection). Lesson: the reverted D-020 rule failed for a different reason than assumed — it starved most users of income, not just user_05.
- **D-024** 2026-09-12 — Free-tier LLM ops: OpenRouter free pools throttle intermittently (429 "rate-limited upstream"); mitigations = batched calls, exponential backoff with Retry-After, per-item disk cache keyed by content hash + provider (a provider-unkeyed cache once served mock results as real — fixed), and model failover (gemma-4-31b throttled -> nemotron 13x slower than nex-n2.5-mini -> nex for text, ling-3.0-flash-vl for vision). Never compete two processes for the same rate-limit pool.
- **D-025** 2026-09-13 — Evidence-income anchor: a just-confirmed salary pays at the NEXT cycle boundary, not on request day. Ceiling test on user_11 proved gold's dip is exactly one month of bills before the first salary lands (gold_min 46,651,245 = start 63.5M − first-cycle bills). Salary "effective from X" pays on X (A/B tested — identical sample scores).
- **D-026** 2026-09-13 — Fixed a cache-poisoning variant in the salary pass: transient batch failures (429) were permanently cached as "no salary fact", silently dropping confirmed salaries (user_11's IDR 38.76M). Failures now leave keys uncached; only well-formed "no fact" responses cache None.
- **D-027** 2026-09-13 — Residual diagnostic (gold-pinned curve minimums): 7-8 sample users already match within rounding; failures cluster into (a) missing income evidence for users whose employer messages state salaries — blocked by OpenRouter free-tier daily cap, a persistent failover filler (tools/salary_filler.py, 6h budget) grinds through it, and (b) small optimistic deltas (~0.5-2M on IDR users) from early-window outflow composition — open.
- **D-028** 2026-09-13 — Offline mode replays the REAL evidence cache: `--offline` previously used a mock-tagged provider whose cache keys could never match, silently generating output.csv with zero message/image evidence. Fixed with an OfflineProvider tagged `openai-compat`; cache misses degrade to mock instead of crashing. Found by an independent flaw-hunt agent; verified by byte-diffing runs.
- **D-029** 2026-09-13 — Recurrence detection hardened (all three verified by independent review + gold cross-checks): (a) stability gate accepts gaps of interval*k (k≥1) so a missed month doesn't kill a stream; (b) clusters split at gaps > 2.2× median interval; (c) dual-pass amount banding (tight 0.8–1.25 separates dual streams/spikes, loose 0.6–1.6 tolerates drift) chosen per category by event coverage, with fragment merging on shared paydays; (d) debit fragmentation falls back to the conservative merge; semi-monthly credit fragments sum into one monthly stream (user_34: 93K+70K → 164K monthly).
- **D-030** 2026-09-13 — Scheduled-credit projection: a scheduled salary row with too-thin history (<3 settled) now projects monthly from its date (gold-verified: request_01 flips to 6/6 exact fields — asp 25256, affordable_now, full_payment, earliest 2024-03-03). Sample score 118 → 124/175 after the three fixes.
- **D-032** 2026-09-13 — Independent code audit (45 findings, two HIGH reproduced live) applied: validator spending-change gate had a leftover loop variable that both admitted below-floor reduces and false-rejected valid ones; wait candidates now must complete by desired_completion_date (PS hard rule; 3 live rows corrected); installment ranking prices the financing fee (PS rule 3); blank max_installment_months = no installments (repo contract); image-pass failures no longer crash the run; llm_client survives malformed 200s and logs the model in the evidence cache tag. Dead code removed: earliest_full_safe (duplicate of decider._earliest_idx), extra_once_debits, dead config branches, unused imports, dead parameters; duplicate parsers (amount/date/plan/changes/fallback) collapsed to single homes; simulate() reduced to a single forward fold. Post-fix verification: 19/19 tests, full-run diff = 9 sub-tolerance float-order rows + exactly the 3 predicted wait rows, sample score 119 -> 124/175.
- **D-033** 2026-09-13 — Audit findings deliberately NOT applied, with reasons: contract/code divergence on early-empty earliest_date with with-changes plans (kept stricter internal gate — recall traded for guaranteed-valid output, D-019); skip general pass for employer messages (token saving vs losing cancellation/delay facts from employer sources); retry amplification in the message fallback (self-heals via cache; final run is offline); reduce_to:0 guard already superseded by floor>0 eligibility; amount formatting stays numeric-tolerant (D-011).
- **D-034** 2026-09-13 — REVERSED the wait-deadline gate (part of D-032) after a single-shot-submission review: the PS gates ONLY partial_payment by the deadline explicitly; affordable_later is defined as "safe later" and not_affordable as "not safe within the forecast period" (90 days, not the deadline); and ranking rule 1 ("complete by desired_completion_date") would be vacuous if late plans were ineligible. Deadline-completion stays as ranking key 1. Zero sample rows affected (all gold waits complete by deadline), so 124/175 holds. Single-shot risk documented both ways; the soft reading is the text-faithful one.
- **D-031** 2026-09-13 — Pre-submission audit of output.csv (single-shot): compliance perfect (250 unique ids, enums, bounds, chronological plans, exact option schedules, 0 validator violations); all 91 not_affordable rows root-caused (65 never safe in 90d — matches gold's empty-earliest style; 23 eligibility-blocked per payment_methods — the PS not_recommended fallback; 0 unexplained); 37 zero-asp rows are the same never-safe population. Residual risk: income-evidence starvation (free-tier cap) makes some curves pessimistic — the known asp frontier, not a validity risk.
- **D-035** 2026-09-13 — Round-2 audit applied (18 findings incl. a real round-1 regression: _log_usage arity made JSON-mode LLM calls fail model-dependently). Validator empty-earliest relaxed to the spec sentence (only affordable_now requires earliest == request_date; affordable_with_plan may have empty earliest when the lump sum is never forecast-safe). linked_event_id lifecycle netting deliberately deferred: the shipped dataset contains zero exact-duplicate rows (verified), the PS states the link alone does not determine cash-flow treatment, and our status/direction filters implement the PS precedence; noted as the known simplification.
- **D-036** 2026-09-13 — Deployment hardening: code.zip now ships the evidence cache (derived artifacts, secrets-scanned) and the usage log, and the keyless default provider is cache-replay — a cold grader run of the documented command reproduces the submitted output.csv byte-for-byte with zero network. Verified in a fresh sandbox.

- **D-037** 2026-09-13 — Final score step 124 → 129/175 (73.7%): the salary-filler evidence refresh landed 50 employer salary facts once the OpenRouter daily cap reset, and fixing a cache-tag mismatch (`_provider_tag` trailing colon made the salary pass read a different namespace than the filler wrote) made all of them visible to the pipeline. Method/plan accuracy jumped 76% → 84% (request_11 went from not_affordable to within one forecast nuance of gold). Also fixed a round-1 regression the round-2 audit caught (`_log_usage` arity broke JSON-mode calls model-dependently). Final shipped distribution: 65 now / 54 with_plan / 54 later / 77 not_affordable. Deployment hardening (D-036) verified by cold grader simulation: byte-identical reproduction of output.csv from a fresh zip with no env and no key.
- **D-038** 2026-09-13 — Fixed the last deployment blemish the judge caught: `OfflineProvider` (the keyless cache-replay client) was writing mock payloads under the REAL provider's cache tag — 16 image keys held amount-0 mock entries while the real extractions sat orphaned under pre-tag keys, leaving the spec's image rule inert in the shipped artifact. Two structural fixes: (1) OfflineProvider is now READ-ONLY (evidence._store refuses writes from replay clients — a cache miss can never poison real keys); (2) all 16 real image extractions migrated onto live keys and 462 mock-tagged entries purged. Verified end-to-end: request_64's pending invoice (event_6033, INR 79,679.26, settles after the request date) is now reserved → asp 0/not_affordable; 129/175 holds; cold grader run reproduces output.csv byte-for-byte.
